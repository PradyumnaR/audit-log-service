# Architecture

## Summary

The Audit Log Service is a tamper-evident, append-only audit log built with Python 3.13, FastAPI, Pydantic, SQLAlchemy and SQLite. Callers write events (who did what, to which resource, when) and query them, but can never update or delete them. Each record is linked to the previous one by a SHA-256 hash over canonically serialized content, forming a hash chain. A verification endpoint walks the chain and reports the first broken record and the type of violation.

Operator-only scripts handle retention and redaction without breaking the chain. Retention archives records older than a configurable window, and redaction removes sensitive payload values that are protected by salted field hashes. Records for an actor or resource can be exported as a bundle that anyone can verify offline.

A read-only compliance report shows regulators who viewed, updated or exported client account data in a time range.

| scenario-a | • **Append-only:** events can be written and queried, never updated or deleted.<br>• **Timestamps:** set by the server in UTC ISO 8601 with `Z`, so there is one source of truth for ordering.<br>• **Hash chain:** each record's SHA-256 hash covers its event fields plus the previous hash, serialized as canonical JSON (sorted keys, fixed format). The first record links to a genesis value derived from the square roots of the first 8 primes.<br>• **Write ordering:** a database write lock handles simultaneous writes one at a time, keeping the chain in order.<br>• **Input validation:** missing fields, bad formats, unknown fields, invalid timestamps and oversized payloads are rejected. `eventType` and `resourceType` are free text in UPPER_SNAKE_CASE, max 64 chars.<br>• **Querying:** filter by actorId, eventType, resourceType (+ optional resourceId, which requires resourceType) and time range, with cursor-based pagination plus limit.<br>• **Verification:** reports whether the chain is intact, or the first broken record with `CONTENT_HASH_MISMATCH` (record data was edited) or `BROKEN_LINK` (previousHash doesn't match the preceding record, e.g. a deleted record).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| scenario-b | • **Retention:** run by an operator script (`make retention`) using `RETENTION_DAYS` from `.env`. There is no public endpoint for it, so it can't be misused.<br>• **Archiving:** sets `archived = true` and clears event content, keeping only id, timestamp, contentHash and previousHash so the chain stays linked. The `archived` flag is not hashed because it changes after the write. Archived records are not returned by queries.<br>• **Archive validation:** archived records must be one continuous block starting at the first record, because retention always archives oldest first. Any gap is reported as `INVALID_ARCHIVE`.<br>• **Redaction scheme:** salted field hashes. Top-level payload keys listed in the `SENSITIVE_FIELDS` config each get a random 32-byte salt and a field hash of SHA-256(salt + canonical value). The content hash uses the field hash in place of the raw value, so removing the value later doesn't change the content hash.<br>• **Redaction:** run by an operator script (`make redact ID=… FIELD=…`). It removes the value and its salt without changing any stored hash, and it isn't exposed through the API, so the API stays append-only. It refuses fields not in `SENSITIVE_FIELDS`, archived records and fields already redacted. Redacted values are shown as `"[REDACTED]"`.<br>• **Verify with sensitive fields:** if the value and salt are present, verify checks that SHA-256(salt + value) matches the field hash. If the field has been redacted, that check is skipped.<br>• **Export:** `GET /audit/export?actorId=…` or `?resourceType=…&resourceId=…` (resourceId requires resourceType, same as queries). The bundle contains metadata, records with all hashed fields plus fieldHashes, salts for unredacted fields, and a `bundleHash` (SHA-256 over contentHashes in id order) that detects added, removed or reordered records. Archived records are left out; redacted records are included with `"[REDACTED]"`.<br>• **Offline verification:** `scripts/verify_bundle.py` uses only the standard library and needs no service or database. |
| scenario-c | • **Assumptions:** "access" means views, updates and exports. "Client account data" means resourceType `ACCOUNT`. Regulators receive data through a report API. Calling systems send the access events. Authentication is out of scope.<br>• **Access event convention:** resourceType `ACCOUNT` + eventType `ACCOUNT_VIEWED`, `ACCOUNT_UPDATED` or `ACCOUNT_EXPORTED`. This reuses the existing event fields, so no schema change is needed.<br>• **Report endpoint:** `GET /audit/reports/account-access?from&to[&resourceId or actorId]`. It is read-only and matches the questions regulators ask: who viewed, updated or exported client account data in a time range, filtered by account or actor.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
